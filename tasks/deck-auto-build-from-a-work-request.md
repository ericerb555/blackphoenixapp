## What already exists, and it is most of it

The deck engine is built and tested — this feature is wiring, an AI read, and
one new record, not a new designer:

    src/app/lib/deckModel.ts        the deck itself
    src/app/lib/framingModel.ts     joists, beams, posts
    src/app/lib/deckStructural.ts   spans and sizing
    src/app/lib/deckBuildSpec.ts    the build spec
    src/app/lib/deckQuote.ts        priced off the model
    src/app/lib/deckAnnotations.ts  dimensions and callouts
    src/app/lib/deckFinishes.ts     decking, rail, skirt
    DeckDesigner.tsx  DeckViewer3D.tsx  DeckStructuralPanel.tsx
    DeckQuotePanel.tsx  DeckPermitPacket.tsx

Records: `design_project:decks:<id>` with `meta.kind = 'deck'`, plus
`design_version:<project>:<version>` — so an as-built and a proposal are two
versions of one project, which is exactly the shape needed.

**The rule this follows is the house rule:** the model OBSERVES, code COMPUTES.
`framingModel` and `deckStructural` size the deck. The AI is never asked for a
joist size, a span, a footing depth or a dollar.

## What is missing

1. **Nothing runs at intake.** `persistWorkRequest` (`workRequests.ts:76`)
   writes `wr:{id}`, `wr_index`, `all_work_requests`, mirrors to the
   `work_requests` table and opens an emergency call. It does not create a
   `pipeline_` item, does not generate a quote, and does not touch the design
   centre.
2. **The quote is generated by a CLICK, in the browser.**
   `AdminAlertsPanel.tsx:342` calls `POST /quote-draft/{wrId}` when Eric opens
   an alert "in pipeline", then writes `pipeline_{wrId}` itself. So the handoff
   lives in a component, runs on one device, and only if somebody clicks.
   `index.tsx:4619` records that a server-side `pipeline_` handoff used to
   exist and was removed.
3. **No deck project is ever created from a request.** The only
   `design_project:decks` record in production is Eric's own, from 2026-08-29.
4. **Project details has no "generate" button** — there is no way to ask for a
   quote by hand, which is why a failed auto-run leaves no recovery.

## The honest constraint: a photograph has no scale

Michael's request carries photos (`media_attachments.photos`) and this:

    description   "Replace deck"
    serviceType   "Full Home Renovation"   (the form's default, not his answer)
    site_address  ""        state  "CA"    (he is in NH)
    estimator_brief  {}

So the intake captured no dimensions, no address and no deck fields at all.
Photos alone cannot give a reliable deck size — there is no reference object
and no EXIF geometry that survives. **Any number invented here becomes a
framed deck, a permit packet and a price.** This project has already deleted
one service that returned `Math.random()` room sizes; this must not become the
second.

The answer is not to guess, it is to ask once and to say what is assumed:

- Read from the photos what a photograph CAN establish: joist direction and
  visible spacing, board run, number of footings and their type, post count,
  beam position, ledger vs freestanding, stair count and run, rail type,
  storeys, visible rot or damage. All as counts and relationships, not lengths.
- Get LENGTH from one of: a stated dimension on the request, a tape measure
  photo, stair-riser count (a known 7"–7¾" rise gives deck height to within an
  inch), or standard board/joist spacing counted across the deck. Each with the
  basis recorded.
- Where length cannot be established, the as-built is marked
  `needsMeasurement: true` with the specific unknown named, and the proposal is
  still produced at a stated assumed size, clearly labelled, for Eric to
  correct in the designer before anything is sent.

## Order of work

Each step is useful alone and none of it needs the next one to ship.

1. **`POST /work-requests/:id/generate` — one server route that does the
   handoff.** Moves what `AdminAlertsPanel` does today onto the server: build
   the `pipeline_{id}` item, call the quote draft, attach it. One place, every
   door, no device. The panel then just calls this.
2. **A "Generate" button in project details and on the pipeline item**, calling
   that route. This is the recovery path, and it is what Eric asked for third:
   "i donthave an option to generate it myself". Ship it before the automation,
   so an auto-run that fails is never a dead end.
3. **Run it automatically after `persistWorkRequest`**, in the background —
   never inside the customer's submit. A quote draft takes up to 90s (the
   15s timeout that threw away paid-for model answers is documented at
   `AdminAlertsPanel.tsx:332`), so the submit must not wait on it. Metered
   through `beginAiCall` with its own bucket and `assertAiAllowed`, reserved
   per image, refunded on every failure path.
4. **`deckObservation.ts` — the AI read.** Two passes over the photos, indexed
   images, counts and relationships only, `{"unsure": true}` permitted, and an
   explicit "what I could not see". Same index-not-identifier rule as
   `beforeAfterPick`: out of range rejects the whole reply.
5. **`deckFromObservation.ts` — observation to a deck model.** Pure, typed,
   tested against hand-written fixtures. Feeds `framingModel` and
   `deckStructural`, which do the actual framing. Produces the **as-built**
   version with `basis` and `assumed` on every figure.
6. **The proposal.** Read the customer's request text (fenced as untrusted,
   `fence()` + `UNTRUSTED_PREAMBLE`) for what they want changed — bigger,
   composite, railings, stairs moved — and emit a second version against the
   as-built. Eric reviews and edits it in `DeckDesigner` before it goes
   anywhere.
7. **Attach both to the work request**, so the quote builder shows them:
   `designProjectId` on the `wr:` record and on the `pipeline_` item, and
   `jobId` on the design project — `design-projects.tsx:334` already writes
   `pipeline_${jobId}`, so that half of the link exists.
8. **Render** through `DeckViewer3D`, and price through `deckQuote.ts` rather
   than the generic estimator, so a deck is quoted by the deck engine.

## Verification

- `node --test tests/deckFromObservation.test.ts` — fixtures first: a ledger
  deck, a freestanding one, stairs on two sides, a deck whose size cannot be
  established (must mark `needsMeasurement`, must not invent a length).
- The same photo set twice must not double the footing count — the
  de-duplication case that the trash estimator plan calls the biggest accuracy
  lever.
- Metered: a row in `ai_call_log` for both passes with non-zero tokens; engage
  the kill switch and confirm the route refuses with no ledger row.
- On Michael's actual request, on production, on an iPhone.
- **Nothing is sent to a customer from this automatically.** It prepares; Eric
  reviews. That is what he asked for and it is also the only safe reading.
